# 验证范围

## 候选版安装验证：2026-10-22

在 Ubuntu 24.04 ARM64、Python 3.12.3 上新建三个相互独立的 venv，各自从构建的 wheel 安装所选渠道及测试依赖。没有读取既有服务凭据，没有连接真实账号或变更现有服务。

| 只安装的渠道 | wheel 安装后离线测试 | 所选可选依赖 |
|---|---|---|
| 微信 | 90 项通过 | 有二维码库，无飞书 SDK、无 websockets 包 |
| 飞书 | 146 项通过、2 项微信可选依赖测试跳过 | 有飞书 SDK；其自身依赖 websockets；无二维码库 |
| QQ | 87 项通过、2 项微信可选依赖测试跳过 | 有 websockets，无飞书 SDK、无二维码库 |

各环境均通过 `pip check`；在源码目录以外成功导入安装后的适配器、执行 `muse-bridge --version`、初始化单渠道配置及离线查看状态。版本为 `0.1.0b1`。源码 sdist 和 wheel 构建成功。

Windows Python 3.13 的完整候选源码测试：305 项通过、2 项 Linux 专属测试跳过。GitHub Actions 按渠道验证 Python 3.11、3.12、3.13，在线结果见 [CI 运行记录](https://github.com/norlingdumar-arch/muse-domestic-bridge/actions/workflows/test.yml)。

安装脚本通过 Bash 语法检查和 Ubuntu 主机的 `--check` 前置检查。**完整 root 安装、创建账号、安装 unit 以及真实扫码流程尚未在全新虚拟机端到端重跑**；本次不为验证候选版而修改正在使用的部署。

## 整理前已有的真实功能验收

下列结果来自原有受控部署，公共候选保留相关传输实现及离线回归；它们不能替代新部署者自己的验收。

- 微信、飞书、QQ 的文字进入同一个已有 Muse 主聊天，回复实际返回。
- VPN 关闭时，飞书和微信消息/系统通知曾完成手机端确认；QQ 完成实际账号私聊收件。
- 飞书完整 30 MiB、微信与 QQ 完整 200 MiB 文件双向往返，字节摘要一致，用户确认能下载和打开。
- Muse WebP 图片转 PNG 后，三个应用都能直接显示和放大。
- 用户从三个应用相册发回不同测试图；Muse 主聊天有对应图片记录，并正确识别各图内随机字符，识别回复返回原渠道。
- 图片和文件任务经过重启检查，已完成任务没有重复提交或投递。

真实账号验收记录、服务器地址、账号标识、聊天数据库、二维码和私有路径没有加入本仓库。测试中的标识和凭据均为占位样本。

## 已知验证边界

没有覆盖所有客户端版本、所有图片格式、最大图片容量、超长停机后的完整补漏、所有账号风控状态或微信长时间不交互后的主动发送。未完成独立安全审计。当前上限是实现约束与既有测试结果，不是平台服务承诺。

## 新部署验收

1. 发送一条独特文字，核对原 Muse 主聊天和聊天应用里的回复。
2. 相册发送一张包含随机字符的图片，核对识别结果及主聊天同步。
3. 先用小文件验证双向收发，再按实际需要验证大文件和摘要。
4. 等待队列空闲后重启服务，确认没有重复提交。
5. 如使用主动提醒，单独验证实际到达时间和应用系统通知；不要把接口接收成功当作准时性保证。
